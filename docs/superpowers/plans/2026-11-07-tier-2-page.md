# Tier 2, plan 2, the page: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One consensus row per fiscal period, so a company FMP reports under two fiscal calendars gets its NTM anchor (B-111, AAPL); then the owner sees the agents' work on the screen: the reviewed value and the stance on the row with a mark beside the ticker, a drawer led by the meter and the report's summary with everything else behind Details, a report page with the charts, the footnotes and the appendixes, an Inbox view with its count in the header, and research requests from the drawer and from a watchlist.

**Architecture:** The server's screen rows and company detail gain the agents' fields, with bulk reads so three thousand rows cost three queries; two new reads serve the drawer's Details and the band's history. The page keeps its shape: one React root per view, `window.FairbandPage` as the shared surface, the design-system bundle with `// fairband:` patches for the stance column, the stance filter, the coverage mark, the meter's second marker, the footnote numbers and the `MultipleHistory` chart. The report page is a new view and script. Every chart reads the series the report's section cites.

**Tech Stack:** Python 3.13, FastAPI; the vendored design-system bundle (React 18, no build step); the page's tests pin the scripts' text as `tests/web/test_app.py` does today.

**Spec:** `docs/superpowers/specs/2026-11-06-tier-2-agents-design.md`, as amended 2026-11-07: sections 16, 18.1 to 18.6, 19 (the Methodology section), 22 and 24 (plan 2); for Task 0, backlog B-111 and `docs/method.md` 5.2 and 5a.2 (the NTM quarters) and the data table's consensus row. Plan 1b (`docs/superpowers/plans/2026-11-07-tier-2-report.md`) built the reads this plan draws from: the references list, the multiples history, the secondary's grid, the sensitivity record.

## Global Constraints

- The constraints of every earlier plan: never print, log or commit a key; never commit vendor data; one imperative sentence per commit with the `Co-Authored-By` line; `uv run ruff check . && uv run ruff format --check . && uv run mypy src && uv run pytest -q` before every commit.
- No policy or valuation-method change: `fairband-mechanical/0.9`, `fairband-policy-v9`, `fairband-review/1`, `fairband-secondary/2` stay as plan 1b left them. Task 0 changes how assembly reads the vendor's consensus rows (one row per fiscal period), an input rule stated in `docs/method.md` in the same commit; every golden and every row without duplicate rows is bit for bit unchanged, and the rows with duplicates (19 refused "incomplete NTM consensus" in refresh 17, AAPL among them) change at the live revalue after the merge, named in the readout.
- The brand book: charts live on the report page only, never on the screen or in the drawer; one series hue and `chart-context`; the diverging pair only for polarity; text never in the series colour; nothing animates; a 2px gap in `surface`, never a stroke; every chart has a table twin behind one page toggle; `ƒ` on a computed number and `◆` on a write, never both on one chip; the three stance words take `stance-buy`, `stance-hold`, `stance-trim`.
- The bundle is patched, not forked: every change in `bundle.js` or `bundle.css` carries a `// fairband:` (or `/* fairband: */`) comment naming the spec section, as the fifty-six existing patches do; `index.d.ts` gains the props.
- The owner neither adds nor drops an override on the page (spec 3); the owner posts a work item, declines one, and adds a note.
- The page's refusal sentences are the server's, shown as they arrive.

## Review Focus

1. A review on an older snapshot after a revalue: the row's `reviewed` is `null` and the cell shows an em dash, never a stale figure (Task 1's `test_a_review_on_an_older_snapshot_is_not_the_rows_reviewed_value`).
2. `Request research` on a company whose item is open: the server's 409 sentence shows under the button and no second item is posted (Task 2's `test_the_request_menu_shows_the_open_item_refusal`).
3. The report page opened for a company with no report: a plain note with a `Request research` path, not a blank panel or an exception (Task 3's `test_the_report_page_without_a_report`).
4. A table cell with no value: the chart leaves a gap, never a zero bar (Task 4's `test_a_missing_cell_is_a_gap`).
5. The Inbox count after the expiry rule posts an item on a read: the header's count moves on the next poll without a reload (Task 5's `test_the_count_follows_the_poll`).
